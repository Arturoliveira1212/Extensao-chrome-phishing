🔀 Teste de Links de Redirecionamento

Esta página contém diversos tipos de links de redirecionamento para testar o PhishGuard

ℹ️ Como Funciona

O PhishGuard agora detecta e analisa o destino final de links de redirecionamento!

Quando você clica em um link de redirecionamento (como Google Ads, rastreadores de email, etc.), a extensão:

  • Extrai automaticamente o URL de destino final dos parâmetros
  • Analisa o destino real, não apenas o link intermediário
  • Mostra AMBOS os URLs (intermediário e final) no aviso
  • Protege você mesmo quando phishers usam serviços legítimos para redirecionamento

🎯 Links de Redirecionamento do Google Ads

Google Ads com Destino Suspeito Suspeito

Exemplo 1: Google Ads → Site com IP
www.googleadservices.com/pagead/aclk?...&adurl=http://192.168.1.1/login
✓ Destino final usa endereço IP (192.168.1.1) - altamente suspeito
Exemplo 2: Google Ads → Domínio Similar ao Banco
www.googleadservices.com/pagead/aclk?...&adurl=https://bancodobrasil-seguro.com/login
✓ Destino final imita "Banco do Brasil" (bancodobrasil-seguro.com)
Exemplo 3: Google Ads → Site Sem HTTPS
www.googleadservices.com/pagead/aclk?...&adurl=http://ofertas-imperdivel.net/premio
✓ Destino final não usa HTTPS e tem palavras suspeitas

Google Ads com Destino Seguro Seguro

Exemplo: Google Ads → Site Legítimo
www.googleadservices.com/pagead/aclk?...&adurl=https://www.google.com
✓ Destino final é site legítimo conhecido (Google)

📧 Rastreadores de Email Marketing

Links de Email com Destinos Variados

Mailchimp → Site Suspeito
mailchi.mp/track?url=http://premio-urgente.xyz/claim
✓ Destino final tem TLD suspeito (.xyz) e palavras-chave de phishing
SendGrid → Homógrafo
sendgrid.net/wf/click?...&redirect=https://аmazon.com/confirm
✓ Destino usa caractere cirílico "а" ao invés de "a" (homógrafo)
Mailchimp → Site Legítimo
mailchi.mp/track?url=https://www.microsoft.com
✓ Destino final é site legítimo (Microsoft)

🔗 Outros Tipos de Redirecionamento

Redirecionadores Genéricos

Redirect com parâmetro "dest"
redirect.example.com?dest=http://fakebank-login.com
✓ Destino tem palavras suspeitas (fake, bank, login)
Redirect com parâmetro "goto"
links.example.com?goto=https://paypal-verify.tk/account
✓ Destino imita PayPal e usa TLD suspeito (.tk)
Redirect com parâmetro "continue"
auth.example.com?continue=http://netflix-payment.ml
✓ Destino imita Netflix e usa TLD gratuito suspeito (.ml)
Redirect com parâmetro "return_url"
portal.example.com?return_url=https://github.com
✓ Destino final é site legítimo (GitHub)

🧪 Casos Complexos

URLs Codificadas e Múltiplos Redirecionamentos

URL Codificada com Destino Suspeito
example.com?url=https%3A%2F%2Ffacebook-security.tk%2Fverify
✓ URL codificada decodificada automaticamente, destino imita Facebook
Protocolo Relativo
redirect.com?target=//suspicious-site.xyz/login
✓ URL com protocolo relativo (//) detectada e analisada

🎯 O Que Esperar ao Testar

Para links com destinos suspeitos:

  • Você verá um aviso destacado mostrando "LINK DE REDIRECIONAMENTO DETECTADO"
  • O link intermediário (Google Ads, Mailchimp, etc.) será exibido
  • O destino final será mostrado em destaque vermelho
  • Os problemas detectados se referirão ao destino final

Para links com destinos seguros:

  • O redirecionamento será detectado mas não bloqueado
  • Você será redirecionado automaticamente para o destino seguro
